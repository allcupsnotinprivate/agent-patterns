# 02. Инструменты и действия

Как агент **действует** во внешнем мире. От базового function calling до кода как действия, управления компьютером и извлечения знаний под управлением агента.

Ключевой совет Anthropic: инвестировать в **agent-computer interface (ACI)** - описания инструментов, форматы аргументов, примеры, poka-yoke-параметры - столько же, сколько в UX для людей. Плохой ACI ломает агента так же, как плохой UI ломает человека.

## Паттерны группы

| Паттерн                   | `id` (папка)       | Суть в одну строку                                                   | Статус      | Карточка |
|---------------------------|--------------------|----------------------------------------------------------------------|-------------|:--------:|
| Function / tool calling   | [`function-calling`](function-calling/) | Модель возвращает структурированный вызов инструмента                | established |  [✅](function-calling/)  |
| Toolformer                | `toolformer`       | Модель сама учится, когда и какие API вызывать (self-supervised)     | emerging    |    ⏳     |
| Gorilla                   | `gorilla`          | LLM, соединенный с массой API; Berkeley Function-Calling Leaderboard | emerging    |    ⏳     |
| CodeAct                   | `codeact`          | Действие = исполняемый код вместо JSON; самоотладка по трейсбекам    | emerging    |    ⏳     |
| Computer use / GUI-агенты | `computer-use`     | VLM видит экран и эмитит click/type/scroll                           | emerging    |    ⏳     |
| Browser-агенты            | `browser-agents`   | Чтение DOM (дешево, точно) либо скриншотов (устойчиво к динамике)    | emerging    |    ⏳     |
| Agentic RAG               | [`agentic-rag`](agentic-rag/) | Извлечение под управлением агента: Self-RAG, CRAG                    | established |  [✅](agentic-rag/)  |

## Порядок чтения

Начать с **function-calling** - это базовый механизм для всей группы. Затем **agentic-rag** (самый частый продакшн-кейс: внешние данные). **CodeAct** - когда действия удобнее выражать кодом (требует песочницы). **Computer use / browser** - когда нет API и приходится работать через интерфейс человека; медленны и уязвимы к prompt injection.

## Компромиссы группы

- **Код как действие** (CodeAct) мощнее JSON-вызовов (композиция библиотек, самоотладка), но **обязательна песочница**.
- **GUI/browser-агенты** снимают требование API, но медленны, хрупки на динамических приложениях и расширяют injection-поверхность.
- **DOM vs скриншоты** у browser-агентов: DOM дешевле и точнее, скриншоты устойчивее к динамическим приложениям.

## Связи с другими группами

- Базовый function calling - механизм действия для [ReAct](../01-reasoning/) (группа 01).
- Agentic RAG опирается на [память и извлечение](../03-memory-context/) (группа 03).
- CodeAct и computer use требуют [sandboxing и защиты от инъекций](../07-infra-safety-eval/) (группа 07) - здесь особенно актуальна «lethal trifecta».
