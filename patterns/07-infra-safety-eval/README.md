# 07. Инфраструктура, безопасность, оценка

Слой продакшена: как агенты соединяются, как их удерживают в безопасных границах и как измеряют. Три подгруппы - **протоколы/фреймворки**, **безопасность**, **оценка**.

## Протоколы и фреймворки

| Тема       | `id` (папка) | Суть в одну строку                                                                           | Статус      | Карточка |
|------------|--------------|----------------------------------------------------------------------------------------------|-------------|:--------:|
| MCP        | `mcp`        | Вертикальный протокол «агент ↔ инструменты/данные» (Anthropic)                               | established |    ⏳     |
| A2A        | `a2a`        | Горизонтальный протокол «агент ↔ агент» (Google → Linux Foundation)                          | emerging    |    ⏳     |
| Фреймворки | `frameworks` | LangGraph / AutoGen / CrewAI / OpenAI Agents SDK / Claude Agent SDK как реализации паттернов | established |    ⏳     |

## Безопасность

| Тема                       | `id` (папка)                | Суть в одну строку                                                                                                            | Статус       | Карточка |
|----------------------------|-----------------------------|-------------------------------------------------------------------------------------------------------------------------------|--------------|:--------:|
| Защита от prompt injection | `prompt-injection-defenses` | Шесть дизайн-паттернов: action-selector, plan-then-execute, LLM map-reduce, dual-LLM, code-then-execute, context-minimization | emerging     |    ⏳     |
| CaMeL                      | `camel-security`            | Первая реализация dual-LLM с провенанс-трекингом и capability-политиками                                                      | experimental |    ⏳     |
| Guardrails + HITL          | `guardrails-hitl`           | Параллельный скрининг + человек на необратимых действиях                                                                      | established  |    ⏳     |
| Sandboxing                 | `sandboxing`                | Изоляция исполнения для CodeAct / computer use                                                                                | established  |    ⏳     |

> **Lethal trifecta** (Willison): опасна комбинация приватные данные + недоверенный контент + внешняя коммуникация у одного агента. Ключевой принцип проектирования безопасности агента - не давать все три сразу.

## Оценка

| Тема              | `id` (папка) | Что измеряет                                                                                      | Статус      | Карточка |
|-------------------|--------------|---------------------------------------------------------------------------------------------------|-------------|:--------:|
| Бенчмарки агентов | `benchmarks` | SWE-bench (кодинг), WebArena (веб), OSWorld (computer use), GAIA (general), τ-bench (tool+диалог) | established |    ⏳     |

> Выбирайте бенчмарк по типу агента, но всегда дополняйте собственными evals на реальных данных. Смотрите **pass^k** (надежность при повторах), а не только pass@1.

## Порядок чтения

**mcp** → **frameworks** (как все соединяется) → **prompt-injection-defenses** + **guardrails-hitl** + **sandboxing** (как удержать в границах) → **benchmarks** (как измерить). **a2a** и **camel-security** - фронтир, читать после базовых.

## Ключевой тезис безопасности

Работа «Design Patterns for Securing LLM Agents against Prompt Injections» переносит защиту из «вероятностного распределения LLM» в **детерминированный код с capability-политиками**. Это дает гарантии класса «инъекция не может выбрать действие» - в отличие от guardrail-промптинга, который лишь снижает вероятность. Оговорка авторов CaMeL: пока и агенты, и их защиты опираются на текущий класс моделей, универсальные агенты вряд ли дадут надежные гарантии безопасности.
