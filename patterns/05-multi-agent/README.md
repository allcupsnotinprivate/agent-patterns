# 05. Мультиагентные топологии

Как **несколько** агентов делят работу и координируются (ось D: одиночный → супервизор → peer-to-peer → граф → blackboard).

**Главная оговорка группы.** Мультиагентность дает выигрыш только на «широких» (breadth-first) параллельных задачах и стоит дорого: ~15× токенов против чата, причем расход токенов объясняет ~80% дисперсии результата. Не используйте ее для тесно связанных задач с зависимостями между агентами (напр., кодинг с зависимостями между файлами). Порог применения: ценность результата > ~15× стоимости токенов. Начинайте с **supervisor/subagents**, а не с peer-to-peer swarm.

## Паттерны группы

| Паттерн                   | `id` (папка)        | Суть в одну строку                                                               | Статус       | Карточка |
|---------------------------|---------------------|----------------------------------------------------------------------------------|--------------|:--------:|
| Supervisor / hierarchical | `supervisor`        | Ведущий агент планирует и делегирует субагентам в изолированных контекстах       | established  |    ⏳     |
| Peer-to-peer / handoff    | `handoff`           | Агенты передают полный контроль друг другу без оркестратора (Swarm → Agents SDK) | emerging     |    ⏳     |
| Blackboard                | `blackboard`        | Общая доска состояния: агенты читают/пишут                                       | emerging     |    ⏳     |
| Debate / society of mind  | `debate`            | Агенты предлагают ответы и критикуют друг друга                                  | emerging     |    ⏳     |
| Role-playing (CAMEL)      | `role-playing`      | Inception-prompting, диалог assistant/user по ролям                              | emerging     |    ⏳     |
| SOP (MetaGPT, ChatDev)    | `sop`               | Стандартные процедуры как цепочка ролевых handoff-ов; «Code = SOP(Team)»         | emerging     |    ⏳     |
| AutoGen group chat        | `group-chat`        | Conversable-агенты, GroupChat с менеджером-селектором спикеров                   | emerging     |    ⏳     |
| Mixture-of-agents         | `mixture-of-agents` | Агрегирование ответов нескольких моделей слоями                                  | experimental |    ⏳     |

## Порядок чтения

**supervisor** (дефолт, изоляция контекста) → **handoff** (децентрализация) → **blackboard** / **group-chat** (общий канал) → **debate** / **role-playing** / **sop** (специализированные протоколы взаимодействия) → **mixture-of-agents**.

## Эмпирика провалов (MAST)

Исследование MAST («Why Do Multi-Agent LLM Systems Fail?») на 1642 аннотированных трейсах дает 14 режимов сбоя в 3 категориях: **Specification Issues** (~42%), **Inter-Agent Misalignment** (~37%), **Task Verification** (~21%). Доли провалов - от 41% до 86,7% по семи SOTA-системам. Вывод: **добавление агентов может ухудшать результат**; topology matters, универсального победителя нет.

Про **debate** отдельно: контролируемое исследование показывает, что главные драйверы качества - внутренняя сила рассуждения и разнообразие группы, а структурные параметры (порядок, видимость уверенности) дают мало.
