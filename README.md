# agent-patterns

База знаний по архитектурным паттернам построения AI-агентов на базе LLM и по проектированию систем с LLM.

Репозиторий разделяет три вида знания, которые накапливаются с разной скоростью:

- **Паттерны** (`patterns/`) - устойчивые карточки. Меняются редко.
- **Статьи** (`papers/`) - поток. Растет по мере исследований.
- **Практика** (`experiments/`) - код и прогоны. Появится, когда будет что фиксировать.

Главный практический принцип, общий для всех первоисточников (Anthropic, OpenAI, LangChain): **начинать с простейшего решения и наращивать сложность только при доказанной пользе.**

## Статусы зрелости

Каждая карточка помечена статусом (в front matter поле `status`):

- **`established`** - устоялось, проверено практикой и множеством реализаций.
- **`emerging`** - набирает силу, но еще не мейнстрим.
- **`experimental`** - исследовательский фронтир, применять с осторожностью.

Разбивку конкретных паттернов по статусам см. в [`Taxonomy`](taxonomy.md#статусы-зрелости).

## Соглашения

- **`id` паттерна** = имя папки в kebab-case (`react`, `plan-and-execute`). По этому `id` карточки ссылаются друг на друга через поле `related`.
- **Метаданные** живут в YAML front matter карточки. Каноническая схема - в [`templates/pattern.md`](templates/pattern.md).
- **Схемы** пишем в Mermaid (`.mmd` или блок ```mermaid) - GitHub рендерит их прямо в markdown.
- **Примеры кода** - минимальные, без фреймворков (голый API + цикл), чтобы была видна суть. Реализации на LangGraph и т.п. кладем отдельно: они устаревают быстрее.
- **Язык репозитория - русский.**

## Рабочий процесс

```
ссылка → papers/inbox.md → заметка в papers/<год>/ → (если родился/изменился паттерн) карточка в patterns/
```

1. Новая ссылка падает в [`papers/inbox.md`](papers/inbox.md) («прочитать потом»).
2. Прочитанная статья получает заметку по шаблону [`templates/paper.md`](templates/paper.md) в `papers/<год>/`.
3. Если из статьи вырастает новый паттерн или она меняет понимание старого - обновляем карточку в `patterns/` и при необходимости переводим ее `status`.

Такой конвейер отделяет «прочитал» от «понял и встроил в систему знаний».

## Структура репозитория

├── README.md                  # эта карта
├── taxonomy.md                # оси классификации, определения групп, статусы
├── glossary.md                # термины
├── patterns/                  # устойчивое знание, одна папка = один паттерн
│   ├── 01-reasoning/
│   ├── 02-tool-use/
│   ├── 03-memory-context/
│   ├── 04-workflows/
│   ├── 05-multi-agent/
│   ├── 06-self-improvement/
│   └── 07-infra-safety-eval/

│   └── inbox.md
└── templates/
    ├── pattern.md             # шаблон карточки паттерна
    └── paper.md               # шаблон заметки по статье

Появятся позже, когда будет материал: `comparisons/` (сравнения паттернов), `guides/` (как выбрать/комбинировать, анти-паттерны), `experiments/` (прогоны), `scripts/` + `.github/workflows/` (автосборка индекса, arXiv-дайджест).
