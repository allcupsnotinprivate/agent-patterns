# Таксономия

Как устроена классификация паттернов в этом репозитории: главная развилка, пять осей, семь групп и лестница статусов зрелости.

## Главная развилка: workflow vs agent

Anthropic в «Building effective agents» (19 декабря 2024) проводит архитектурное различие:

- **Workflow** - система, где LLM и инструменты оркестрируются через **заранее заданные пути в коде**. Предсказуемо, дешево, инспектируемо. Негибко.
- **Agent** - система, где LLM **динамически управляет** своим процессом и использованием инструментов. Гибко. Дороже, труднее отлаживать.

Это первая развилка при выборе паттерна. Рекомендация первоисточников: **находить простейшее возможное решение и наращивать сложность только при необходимости.** Порог перехода от workflow к agent: путь нельзя захардкодить, но прогресс можно верифицировать (тесты, состояние БД).

## Оси классификации

По этим осям удобно раскладывать любой паттерн. Они ортогональны группам: один паттерн получает координату по каждой оси.

- **Ось A - автономность / контроль потока:** workflow (детерминированный код-путь) ↔ agent (модель ведет себя сама).
- **Ось B - что оптимизируется / эволюционирует:** промпт → память/навыки → инструменты → топология → сам код агента.
- **Ось C - форма поиска в пространстве решений:** цепочка → выборка + голосование → цикл → дерево → граф.
- **Ось D - число агентов и топология:** одиночный → супервизор/иерархия → peer-to-peer / handoff → граф/сеть → blackboard.
- **Ось E - стадия жизненного цикла:** рассуждение → действие → память → координация → самоулучшение → инфраструктура → безопасность → оценка.

## Семь групп

Нумерация задает порядок чтения. Slug группы (в скобках) используется в поле `group` карточки.

### 01. Рассуждение и планирование (`reasoning`)
Как **одиночный** агент думает. Лестница по «форме поиска» (ось C): линейная цепочка (CoT) → выборка нескольких путей и голосование (Self-Consistency) → цикл размышление-действие-наблюдение (ReAct) → отделение плана от наблюдений ради экономии (ReWOO) → параллельный DAG задач (LLMCompiler) → деревья и графы мыслей (ToT/GoT) → полноценный поиск по дереву с обратной связью среды (LATS) → итеративное самоисправление (Reflexion/Self-Refine/CRITIC).

### 02. Инструменты и действия (`tool-use`)
Как агент **действует** во внешнем мире. От базового function/tool calling до кода как действия (CodeAct), GUI/browser-агентов и agentic RAG (Self-RAG, CRAG). Ключевой совет Anthropic: инвестировать в agent-computer interface (ACI) столько же, сколько в UX для людей.

### 03. Память и контекст (`memory-context`)
Что агент **помнит** между шагами и сессиями. Эталонная классификация - CoALA: рабочая память + три долговременных (эпизодическая, семантическая, процедурная). Сюда же - context engineering, суммаризация, scratchpad, skill libraries, изоляция контекста субагентов.

### 04. Workflow-паттерны (`workflows`)
Пять детерминированных паттернов оркестрации от Anthropic: prompt chaining, routing, parallelization (sectioning/voting), orchestrator-workers, evaluator-optimizer. Применять, когда задача декомпозируема и путь предсказуем.

### 05. Мультиагентные топологии (`multi-agent`)
Как **несколько** агентов делят работу и координируются: supervisor/hierarchical, peer-to-peer/handoff (Swarm), blackboard, debate, role-playing (CAMEL), SOP (MetaGPT/ChatDev), AutoGen group chat, mixture-of-agents. Дают выигрыш только на «широких» задачах и стоят ~15× токенов.

### 06. Самоэволюция (`self-improvement`)
Как система **улучшает сама себя** - по оси B (что эволюционирует): промпты (DSPy, TextGrad, GEPA), навыки (Voyager), топология (GPTSwarm, AgentSquare), сам код (ADAS, AFlow, Gödel Agent, Darwin Gödel Machine), веса (agentic RL). Требует замороженного бенчмарка, который агент не может править.

### 07. Инфраструктура, безопасность, оценка (`infra-safety-eval`)
Слой продакшена: протоколы (MCP, A2A), фреймворки (LangGraph, AutoGen, CrewAI, Agents SDK), безопасность (guardrails, HITL, sandboxing, dual-LLM/CaMeL, защита от prompt injection), оценка (SWE-bench, WebArena, OSWorld, GAIA, τ-bench).

## Статусы зрелости

Поле `status` карточки принимает одно из трех значений. Разбивка ниже - по состоянию на 2025-2026 и будет уточняться по мере наполнения.

| Статус         | Значение                                               | Примеры                                                                                                                                                                                               |
|----------------|--------------------------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `established`  | Устоялось, проверено практикой и множеством реализаций | CoT, Self-Consistency, ReAct, Reflexion/Self-Refine, Plan-and-Execute/ReWOO, RAG/agentic RAG, function calling, пять workflow-паттернов Anthropic, supervisor/subagents, MCP, A2A, основные бенчмарки |
| `emerging`     | Набирает силу, но еще не мейнстрим                     | context engineering как дисциплина, dual-LLM/CaMeL, reasoning-модели как замена части скаффолдов, DSPy/GEPA для промптов                                                                              |
| `experimental` | Исследовательский фронтир                              | ADAS, AFlow, Gödel Agent, Darwin Gödel Machine, mixture-of-debaters, полностью автономные self-evolving-системы, многие протоколы агентной коммуникации                                               |

## Ключевой сдвиг 2025-2026

Reasoning-модели с test-time compute (o1/o3, DeepSeek-R1, Claude extended thinking) **интернализуют** планирование, само-рефлексию и переключение thought/action внутрь модели. Из-за этого часть внешних скаффолдов (явные ToT-деревья, ручные планировщики) упрощается или заменяется одним вызовом рассуждающей модели.

**Осторожно:** первоисточники поддерживают лишь *направление* (интернализация планирования), а не полную отмену структурных паттернов. На трудных/неоднозначных задачах с проверяемыми промежуточными состояниями ToT и явные планировщики все еще дают выигрыш. Категоричные формулировки («ToT больше не нужен») встречаются в отраслевых блогах, а не в первоисточниках.
